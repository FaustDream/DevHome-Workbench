# 2026-06-18

## 文件系统配置持久化严重 bug 修复 (v1.4.1)

### 问题
每次新开标签页都弹出配置目录选择对话框。只有浏览器一直存在一个已开的新标签页时才不会触发。

### 根因
`fileConfig.js` 的 `init()` 在启动时调用 `verifyPermission(handle, true)` 验证 `readwrite` 权限。当所有扩展标签页都关闭后，Chrome 不会自动恢复 File System Access API 的 `readwrite` 权限；`requestPermission({mode:'readwrite'})` 在页面加载时无用户手势上下文中抛出 `NotAllowedError`，被静默 catch → 触发 `clearHandleFromDB()` 删除 IndexedDB 中的 handle → 下次启动又需要重新选择目录。

### 修复方案
1. **启动阶段分离 read/write 权限**：`init()` 仅验证 `read` 权限来读取配置文件，`isReady` 即使 write 待授权也设为 `true`
2. **延迟 write 权限请求**：write 权限在用户手势上下文（点击警告条按钮）或实际写入时才请求
3. **新增 `tryRecoverWritePermission()`**：用已有 handle 恢复 write 权限，避免弹出完整目录选择器
4. **警告条按钮智能处理**：`writePermissionPending` 时先尝试恢复权限，失败才弹出目录选择器
