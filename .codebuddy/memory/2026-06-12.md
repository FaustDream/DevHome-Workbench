## Bug 修复：分类浮窗 (category-popover) 点击无效

### 第一次尝试（CSS pointer-events — 无效）
- **错误假设**：CSS `pointer-events: none` 阻止了点击
- **修复**：在 `.category-popover-item` 上添加 `pointer-events: auto`
- **结果**：无效，日志显示 `pointer-events: auto` 一直正常工作

### 根因定位（通过全链路日志）
- **关键日志**：
  ```
  [PopoverMouseDown] mousedown 到达 popover! target: BUTTON category-popover-item
  [ShowPopover] 显示弹窗          ← focusin 触发于此！
  [RenderPopover] 渲染弹窗 ...    ← innerHTML 替换！
  ```
- **死锁机制**：`mousedown` 按下按钮 → `<button>` 获得焦点 → `focusin` 冒泡到 `pageIndicator` → `pageIndicator` 上的 `focusin` 处理器调用 `showCategoryPopover()` → `renderCategoryPopover()` → `innerHTML = ...` **销毁了被点击的按钮** → 等 `click` 事件到达时，目标按钮已不存在

### 修复三 (最终)：三层防御彻底消除点击失效 (`categoryUI.js` + `events.js`)

**已识别的三种点击破坏场景：**
1. `focusin` 在 mousedown 期间触发 `showCategoryPopover` → `innerHTML` 替换 → 按钮销毁
2. CSS `:hover` 先于 JS `mouseenter` 使弹窗可视可点 → `category-menu-open` 未设置 → `showCategoryPopover` 判定为"关闭→打开" → re-render → 按钮销毁
3. `renderCategoryPopover` 的 `innerHTML` 替换 → `focusout` 冒泡 → 180ms 关闭计时器 → 弹窗被关 → 下次点击需重新 hover 打开

**三层防御：**
1. `renderCategoryPopover` 开头设 `popoverMouseDown` 守卫 — mousedown 期间禁止 re-render
2. `showCategoryPopover` 改为**原地更新**（更新计数和 active 状态，不替换 innerHTML），仅在按钮数与分类数不匹配时才全量渲染
3. `renderCategoryPopover` 中 `clearTimeout(categoryPopoverCloseTimer)` — 防止 focusout 关闭计时器

## Bug 修复：上一页/下一页图标消失
- **根因**：CSP `extension_pages: "script-src 'self'; object-src 'self'"` 未阻止样式表加载，但 CDN 字体文件可能间歇性失败；同时 `page-indicator` 的 `backdrop-filter: blur(12px)` 创建独立合成层，与 `opacity: 0.8` 结合在 Chrome 某些版本中会导致字体图标渲染异常
- **修复**：prev/next 按钮的 `fa-chevron-left/right` 替换为内联 SVG（`stroke="currentColor"` 继承按钮颜色），彻底消除 CDN 和字体渲染依赖

## Bug 修复：开发工作台下右键菜单被遮挡
