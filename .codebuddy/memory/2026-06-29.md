# 2026-06-29 工作日志

## 第六轮修复：fetch eval 限制 + 完整兜底

### 根因
- 用户连续报告"动态加载 PM bundle 后仍不可用"
- 排查发现：
  1. CSP `script-src 'self'` 阻止 `new Function(code)` 动态代码执行（不安全）
  2. `<head>` 中同步 `<script src>` 标签在 Chrome 扩展 newtab 页面中也不一定执行成功
  3. 动态 `<script>` onload 触发后 IIFE 内部 `window.PM = {...}` 可能未完成

### 修复
- 移除 fetch + eval 方案（CSP 违规）
- 保留 `<head>` 中静态同步加载（最可靠位置）
- 保留动态加载作为兜底（`script-src 'self'` 允许同源动态 script）
- 增强轮询机制：onload 后 5 秒内每 50ms 检查 window.PM
- 增强错误日志：精确区分 onerror / onload 成功 / 超时 / 已有 script 标签

### 根因
- 用户报告 `[PM编辑器] 动态加载 PM bundle 后仍不可用`
- `_loadPMBundle` 的 `onload` 触发 resolve，但 `window.PM` 仍为 `undefined`
- 原因：Chrome 扩展中动态创建的 `<script>` 的 `onload` 只表示 HTTP 加载完成，PM bundle 内 `window.PM = {...}` 的赋值可能在 onload 之后才执行（特别是大文件）
- 附加根因：模块加载时 + 首次 `pmCreateEditor` 时都触发了动态加载，导致两个 Promise 互相覆盖

### 修复
- `_loadPMBundle` 改为 onload 后**轮询** `window.PM`（50ms × 100次 = 5s 超时）
- 添加 `_pollUntilPMReady()` 工具函数
- 移除模块加载时的自动触发，避免与 _ensureInit 中的加载冲突
- 保留 `_pmLoadPromise` 单例，确保并发调用共享同一 Promise

## ProseMirror 编辑器无法编辑修复

### 问题
- 光标无法进入编辑区，控制台报错 `[PM编辑器] pm.bundle.js onload 后 5s 内 window.PM 仍不可用`
- 根因：`<script src="js/lib/pm.bundle.js">` 放在 `<head>` 中，在 Chrome 扩展 MV3 newtab 页面特殊上下文里没有正确执行
- 导致 `window.PM` 始终为 undefined，ProseMirror 无法初始化，连 contenteditable 回退也受影响

### 修复
- 将 `pm.bundle.js` 从 `<head>` 移除，放到 `<body>` 末尾（所有 deferred 脚本之前）
- 不使用 `defer`，确保同步加载和执行
- 添加 `data-pm-loaded="1"` 属性防止动态加载器重复创建

### 深入修复：chrome.runtime.getURL() 动态加载

### 问题
- 静态 `<script src>` 和相对路径动态 `<script>` 在 chrome://newtab/ 页面中均无法正确执行
- Chrome newtab 页面的相对路径可能无法映射到扩展的实际文件路径
- 错误：`PM timeout (existing)` — 脚本标签存在但 window.PM 始终未赋值

### 根因
- Chrome 扩展 newtab 页面的 URL 是 `chrome://newtab/`，但扩展文件位于 `chrome-extension://[id]/`
- `script-src 'self'` 中 `'self'` 只匹配扩展的 origin (`chrome-extension://[id]`)
- 相对路径 `<script src="js/lib/pm.bundle.js">` 在 newtab 页面可能解析为 `chrome://newtab/js/lib/pm.bundle.js`，不在扩展 origin 下

### 修复
- 完全移除静态 `<script>` 标签
- `_loadPMBundle()` 改用 `chrome.runtime.getURL('js/lib/pm.bundle.js')` 获取 `chrome-extension://[id]/js/lib/pm.bundle.js` 绝对路径
- 在模块初始化时（而非首次打开编辑器时）立即触发加载，消除延迟
- 增加详细 src 日志便于排查
