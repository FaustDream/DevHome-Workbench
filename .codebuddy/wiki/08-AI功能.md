# 08 AI 功能

> 本章覆盖 AI 能力：模块注册表（ai-modules）、供应商管理（ai-providers）、对话面板（ai-chat）、调用引擎（dashboard 的 generateAI）。

## 8.1 `js/ai-modules.js` — AI 功能模块注册表

**挂载点**：`ns.AI_MODULES`、`ns.getModuleById`

**职责**：定义可扩展的 AI 功能模块清单。每个模块包含 ID、名称、描述、System Prompt、上下文构建函数、调用约束。

### 8.1.1 模块定义结构

```js
{
  id: 'daily-summary',
  name: '每日总结',
  description: '基于今日笔记和捕获生成结构化工作总结',
  systemPrompt: '你是一个专业的工作总结助手。…Markdown 格式输出…',
  buildContext: function () { /* 组装上下文文本 */ },
  emptyMessage: '今天还没有任何记录',   // 无内容提示
  requireContent: true,                 // 无内容是否禁止调用
  needUserInput: true,                  // 是否需要用户输入
  inputPlaceholder / inputTitle         // 输入框配置
}
```

### 8.1.2 内置模块

| ID | 名称 | 说明 | 约束 |
|----|------|------|------|
| `daily-summary` | 每日总结 | 汇总今日笔记+捕获为结构化总结（今日完成任务/问题/收获/明日计划） | `requireContent:true`；`buildContext` 过滤当天 notes+captures 拼接 |
| `quick-chat` | 快速对话 | 自由提问即时回答 | `needUserInput:true`；无上下文 |

**扩展方式**：只需向 `ns.AI_MODULES` 数组新增对象，无需改调用方。

## 8.2 `js/ai-providers.js` — AI 供应商

**挂载点**：`ns.getProviderById`、`ns.createOpenAIProvider`、供应商元数据注册表

**职责**：管理 AI 供应商的元数据与 API 适配器。

### 8.2.1 供应商类型

| 类别 | 说明 |
|------|------|
| **内置供应商** | 混元（hunyuan）等，元数据含 apiKey/endpoint/model + 请求适配器 |
| **自定义（OpenAI 兼容）供应商** | 通过 `createOpenAIProvider(providerId, providerConfig)` 动态创建，使用通用 OpenAI 兼容适配器 |

### 8.2.2 供应商元数据结构

```js
{
  id, name,
  apiKey, endpoint, model,        // 默认值（用户配置覆盖）
  request(message, opts)          // API 适配器：构建请求、处理响应（支持流式）
}
```

### 8.2.3 配置来源

`v2/config.aiApi`：

```js
{
  activeProvider: 'hunyuan',
  providers: {
    hunyuan: { apiKey, endpoint, model },
    custom: { apiKey, endpoint, model }
  }
}
```

## 8.3 `js/ai-chat.js` — AI 内联对话面板

**挂载点**：`ns.aiChat`（`open` / `toggle` / `send` / `save` / `clear` 等）

**职责**：页面底部内嵌对话面板：显示/折叠/关闭、消息历史、调用 generateAI 发送消息、渲染 Markdown 回复、保存对话为笔记。

### 8.3.1 存储

`CHAT_STORAGE_KEY = 'ai_chat_history'`（chrome.storage.local）——刷新不丢失。

### 8.3.2 DOM（懒初始化 `ensurePanel`）

```html
<div id="aiChatPanel" class="ai-chat-panel minimized">
  <div class="ai-chat-header" id="aiChatHeader">
    <div class="ai-chat-header-left">
      <span class="ai-chat-header-dot"></span>
      <span class="ai-chat-header-title">AI 对话</span>
      <span class="ai-chat-model-select" id="aiChatModelSelect">
        <span class="ai-chat-header-badge" id="aiChatBadge">混元</span>▾
      </span>
    </div>
    <div class="ai-chat-header-actions">
      <button id="aiChatSaveBtn">💾 保存</button>
      <button id="aiChatClearBtn">🗑</button>
      <button id="aiChatMinBtn">−</button>
      <button id="aiChatCloseBtn">×</button>
    </div>
  </div>
  <div id="aiChatModelDropdown" style="display:none"></div>
  <div class="ai-chat-messages" id="aiChatMessages">…空状态…</div>
  <div class="ai-chat-input-area">
    <textarea id="aiChatInput" placeholder="输入问题，Enter 发送..."></textarea>
    <button id="aiChatSendBtn">发送</button>
  </div>
</div>
```

### 8.3.3 交互

- 头部点击 → 展开/折叠（`toggleChat`）。
- 最小化 → 折叠；关闭 → 完全隐藏（`hideChat`）。
- 模型选择器 → 下拉（`toggleModelDropdown`），选中 `switchChatProvider(providerId)`。
- 发送 → `generateAI('quick-chat', input)` → 回复渲染 Markdown（`sanitizeHtml(marked.parse(...))`）。
- 保存 → 将对话历史存为笔记（createNote）。
- 清空 → 清空消息与存储。
- **快捷键**：Ctrl+I 打开（global-events）。

### 8.3.4 事件防泄漏

- `documentClickHandler` 引用显式管理，避免下拉外部点击监听器多次注册累积泄漏。

## 8.4 `js/workbench_private/_dashboard.js` — AI 调用引擎

（详见第 06 章 6.5.2）核心逻辑：

1. 模块查表 → 配置读取 → 供应商解析（内置/自定义通用适配器）→ 合并配置 → 无 Key 拦截 → 发起请求。
2. 请求失败/网络异常处理、回复渲染。
3. 供应商未配置 Key 时 toast 引导配置。

## 8.5 AI 数据流全景

```
[用户] 对话面板输入
  → ns.aiChat.send() → generateAI('quick-chat', input)
  → 读 v2/config.aiApi → 供应商适配器 → HTTP 请求（流式/非流式）
  → 回复文本 → sanitizeHtml(marked.parse()) → 渲染气泡
  → 消息历史持久化 v2/ai_chat_history（chrome.storage.local）
  → [保存] → createNote({title:'AI 对话', content: 对话HTML})
```

## 8.6 重构要点（AI 功能）

1. **供应商适配器与 AI 模块**都采用注册表模式，扩展性好；但缺少统一「请求失败重试/超时/错误分类」层。
2. **密钥存于 chrome.storage（明文）**：v2/config.aiApi.providers[].apiKey 未加密，可评估 chrome.storage.session + 加密或提示用户风险。
3. **对话历史无限增长**：`ai_chat_history` 无条数上限，需截断策略。
4. **`daily-summary` 上下文直接拼 HTML 内容**：含标签可能污染 prompt，建议纯文本化。
5. **`needUserInput` / `requireContent` 两套约束**可统一为「运行前校验函数」。
6. **Markdown 渲染**依赖 `marked` + 轻量 `sanitizeHtml`，安全边界需评估（建议 DOMPurify）。
