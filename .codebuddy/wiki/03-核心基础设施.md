# 03 核心基础设施

> 本章覆盖所有业务模块依赖的底层设施：全局状态（`state`）、DOM 缓存、工具函数、日志、图标、密钥与常量。

## 3.1 `js/state.js` — 全局状态与 DOM 缓存

**挂载点**：`ns.state`（状态）、`ns.dom`（DOM 引用）

**职责**：集中管理跨模块共享的应用状态，并缓存高频使用的 DOM 节点引用（避免反复 `document.querySelector`）。

## 3.2 `js/utils.js` — 工具函数

**挂载点**：`ns.escapeHtml`、`ns.sanitizeHtml`、`ns.renderEngineIcon`、`ns.normalizePageState`、`ns.getTileIdentity`、`ns.getPageTileSignature`、`ns.repairDefaultCategoryContent`、`ns.createDefaultTile`、`ns.getDefaultPagesData` 等

| API | 说明 |
|-----|------|
| `escapeHtml(str)` | 基于 `div.textContent` 的 HTML 转义 |
| `sanitizeHtml(html)` | 轻量 HTML 净化（剔除 script/style/iframe/object/embed/link/meta/base + `on*` 属性 + javascript:/data:text/html 协议）——用于渲染 AI Markdown 输出，低成本防护，注释建议强保障引入 DOMPurify |
| `renderEngineIcon(engine)` | 搜索引擎图标渲染：优先 `iconName`（SVG symbol），其次 `badge` 文本，其次 `svg` |
| `normalizePageState(pagesData, storedPageNames)` | 修复分类名错位：以 `page.name || page_names[i] || '第N页'` 归一化 |
| `getTileIdentity(tile)` | 磁贴身份指纹 `label|url` |
| `getPageTileSignature(page)` | 页面磁贴签名（按 identity 排序拼接）——用于分类内容修复 |
| `repairDefaultCategoryContent(pagesData, pageNames, defaultPagesData)` | 默认分类内容错位修复算法（见下） |
| `createDefaultTile(item, idx, seed)` | 创建默认磁贴 `{id:'tile_<seed>_<idx>', label, url, type:'favicon', icon:'', color:'#4a9eff', position:idx}` |
| `getDefaultPagesData()` | 读取 `defaults.json` 缓存（`tabpage_defaults_cached` + 版本号校验 `DEFAULTS_VERSION`） |

### 3.2.1 关键算法：`repairDefaultCategoryContent`

1. 若 pages 与默认页数不一致 → 不修复。
2. 建立「默认页名→页」「默认页名→签名」「签名→默认页名」三张映射。
3. 若任意页名不在默认页名中 → 不修复。
4. 遍历：若当前页签名 ≠ 预期默认签名，且当前签名能匹配到另一个默认页名（≠预期名），判定需要修复。
5. 修复：按 `pageNames[i]` 重建每页 tiles，并补 `position` 字段。

该算法用于修复历史上「分类重命名导致默认磁贴内容串位」的数据问题。

## 3.3 `js/logger.js` — 日志体系

**挂载点**：`ns.logger`

**职责**：统一日志入口，按级别输出，供 `boot` 等使用。

| API | 说明 |
|-----|------|
| `ns.logger.info(module, msg, extra?)` | 信息日志 |
| `ns.logger.warn(module, msg, extra?)` | 警告 |
| `ns.logger.error(module, msg, extra?)` | 错误（StorageV2 乐观锁失败时调用） |

> **重构注意**：实际项目中大量模块仍直接使用 `console.log/warn/error`（带 `[分类]` 前缀，符合 AGENTS.md 交互日志规范），未全部收敛到 `ns.logger`。日志收敛是重构项之一（见第 13 章）。AGENTS.md 要求交互日志格式：`[交互]`、`[面板]`、`[编辑]`、`[警告]`、`[错误]`、`[模式]`。

## 3.4 `js/icons.js` — 图标体系

**挂载点**：`ns.icon(name, className?)`

**职责**：渲染 Lucide 风格内联 SVG 图标。图标来源：
- `index.html` 中 `<svg id="dhIconSprite">` 定义的 `symbol`（`dh-icon-*`）。
- `icons.js` 内置的路径映射。

**用法示例**：`ns.icon('x', 'dh-icon--sm')`、`ns.icon('plus', 'dh-icon--sm')`、`ns.icon(name, 'dh-icon--md')`。

**语义图标名**（天气、引擎等）：`weather-sun`、`weather-cloud-sun`、`weather-cloud`、`weather-rain`、`weather-snow`、`weather-fog`、`weather-storm`、`weather-snowflake`、`weather-thermometer`、`engine-*` 等。

## 3.5 `js/secrets.js` — 密钥管理

**挂载点**：`ns.secrets`（或全局常量）

**职责**：管理第三方服务 API Key 的存取。目前实际承载：**Google 搜索可达性检测的密钥配置**（proxyManager 依赖）等。密钥不硬编码在代码中，从配置读取。

> 注意：`js/secrets.js` 在 .gitignore 中（untracked），为本地密钥文件，不在代码库。重构时需保证不将该文件提交。

## 3.7 基础弹窗体系（ns 级）

> 弹窗禁止使用浏览器原生 `alert/confirm/prompt`，统一走自定义弹窗。这些定义在 `ui/_tile-editor.js`（通用弹窗工厂）与 `shadcn-dialogs.js`。

| API | 说明 |

## 3.8 重构要点（基础设施层）

1. **`ns.dom` 是脆弱的全局 DOM 引用**：一旦 HTML 结构调整，所有引用失效，需建立「DOM 引用注册表 + 缺失警告」机制。
2. **`ns.state` 无类型约束**：大量字段靠命名约定维护，建议引入类型定义（JSDoc 或迁移 TS）。
3. **日志双轨**：`ns.logger` 与 `console.*` 并存，需统一。
4. **`sanitizeHtml` 为轻量净化**：若渲染不可信内容升级场景，需引入 DOMPurify。
5. **`config.js` 常量分散**：部分常量散落在各模块文件内（如 weather 的 TTL、storageV2 的 TTL），应集中。
