# 01 项目概览与总体架构

## 1.1 项目定位

**Thrilled** 是一个 Chrome Manifest V3 扩展，将「新标签页」改造为个人工作台。核心能力：

- **日常模式（daily）**：整页新标签页，包含搜索、时间日期、每日问候、天气、磁贴快捷方式、分类分页、倒计时、壁纸/主题/背景。
- **专注模式 / 工作台（workbench）**：四象限任务管理、番茄钟、日历、行为仪表盘、笔记系统（富文本 + 笔记本 + 快速捕获 + 网页剪藏）、AI 对话与 AI 功能模块、Markdown 导出。
- **网页剪藏**：右键菜单「剪藏到工作台」，由 Service Worker 捕获选区内容。
- **任务到期通知**：后台 alarms 每 15 分钟检查任务到期，发 Chrome 通知。
- **文件系统配置同步**：通过 File System Access API 将配置导出到本地 `devhome-config.json`，支持备份/恢复。

## 1.2 技术栈

| 维度 | 技术选型 | 说明 |
|------|---------|------|
| 语言 | JavaScript（ES5 风格 IIFE + ES6 语法混合） | 页面脚本不经过打包（直接 `<script>` 引入），故用 IIFE + `window.DevHome` 命名空间 |
| 后台 | Service Worker（`js/background.js` + `importScripts` 加载 `bg/` 子模块） | MV3 标准，无页面级后台 |
| 富文本 | Tiptap（`@tiptap/core` + starter-kit + task-list + highlight + text-style 等） | 构建时打包为 `js/tiptap-bundle.js` |
| 样式 | 纯原生 CSS + Semantic Token（CSS 变量） | 无 CSS 框架运行时；`css/tailwind-base.css` 仅做 Shadcn 组件变量桥接 |
| React | React 18（生产构建）+ Shadcn/ui 组件 | 仅用于仪表盘、Toast、Dialog 等个别组件，JSX 源码在 `js/components/`，编译产物在 `js/ui-components/` |
| Markdown | `marked.min.js` | AI 回复渲染 |
| 日期 | `dayjs.min.js` | 部分模块使用 |
| 存储 | `chrome.storage.local` + `localStorage` + 文件系统 | 三层结构，见第 02 章 |
| 构建 | Node 脚本 `build.mjs` | JSX 编译、Tiptap 打包、业务 JS 拼接、CSS 合并 |

## 1.4 模块分层架构

项目采用「**编排入口 + 私有子目录**」的分层模式，业务逻辑不集中在单文件，而是拆分为入口 + 子模块：

```
┌─────────────────────────────────────────────────────┐
│                  页面层 (HTML)                        │
│  index.html / popup.html / sidepanel.html            │
├─────────────────────────────────────────────────────┤
│              编排入口层 (js/*.js)                     │
│  main.js(启动) background.js(SW) workbench.js notes.js│
│  events.js ui.js                                     │
├─────────────────────────────────────────────────────┤
│            业务模块层 (js/*.js 单文件)                 │
│  tiles categoryUI search navigation linkOpener       │
│  theme-manager bgManager wallpaper matrix-bg countdown│
│  weather dailyGreetingCard quotes favicon proxyManager│
│  ai-chat ai-modules ai-providers export              │
├─────────────────────────────────────────────────────┤
│            私有子模块层 (js/<模块>/_*.js)              │
│  bg/    _pomodoro-core _pomodoro-broadcast _clip-    │
│         capture _task-notify _quotes                 │
│  notes/ _notes-crud _notes-notebook _notes-capture   │
│         _notes-view _notes-editor _notes-filter       │
│  events/ _global _toolbar _settings _search _pomodoro│
│         _quadrant _calendar _category _notebook _filter│
│         _misc                                       │
│  ui/    _context-menu _settings-panel _tile-editor   │
│  workbench_private/ _quadrant-tasks _pomodoro _calendar│
│         _dashboard _notes-workbench                  │
├─────────────────────────────────────────────────────┤
│              数据服务层 (js/*.js)                     │
│  storage(localStorage) storageV2(chrome.storage)     │
│  dataService(统一门面) fileConfig(文件系统)            │
├─────────────────────────────────────────────────────┤
│              基础工具层 (js/*.js)                     │
│  state(全局状态+DOM缓存) utils logger icons secrets   │

└─────────────────────────────────────────────────────┘
```

**命名空间模式**：所有页面脚本通过 IIFE 注入 `window.DevHome`（别名 `ns`），子模块共享 `ns.state`、`ns.dom`、`ns.storage` 等。这是本项目最重要的架构约定——**所有模块是同一个全局对象的属性，通过命名空间互相调用，无模块化 import/export**。

## 1.6 版本规则

- 小问题 → 版本 +0.0.1；多问题 → +0.1.0；大问题 → +1.0.0。
- 10 个小版本 = 1 个中版本；10 个中版本 = 1 个大版本。
- 每次代码修改后：更新版本号 → 自测 → git 提交并推送。

## 1.8 启动序列（main.js `ns.boot`）

`boot()` 按 Phase 顺序执行，兼顾「首屏快渲染」与「数据后加载」：

- **Phase 0**：`theme.init()` 主题初始化（0 开销）。
- **Phase 1**：并行启动 `storageV2.migrateFromLegacy()`（数据迁移）与 `fileConfig.init()`（文件配置），两者无依赖。`proxyManager.init()` 异步初始化不阻塞。
- **Phase 2**：立即渲染首屏 UI：`initEngine()`（搜索引擎）、`applyShortcutSize/Columns`（快捷方式尺寸）、`applyLayoutConfig()`（F5 布局）、`openFaviconDB()`（IndexedDB）、`tileManager.load()` + `renderTiles()`（先用缓存渲染）。
- **Phase 3**：V2 数据并行加载：`notesManager.load()` + `loadCaptures()` + `loadNotebooks()` + `CONFIG`（读取 `lastNotebookId`、`focusShortcut`）。数据就绪后无条件重渲染磁贴。
- **Phase 4**：同步 UI 状态：自动聚焦、分类记忆（恢复 last_page）、`applyCategoryButtonMode`、`syncSettingsControls`、`bindEvents()`。
- **Phase 5**：`requestAnimationFrame` 延迟加载非首屏模块：`initDailyGreetingCard`、`initWeather`、`syncTaskNotifySettings`、`initReactToast`。
- **Phase 6**：日志收尾；「刷新恢复」逻辑（仅 reload 时恢复专注模式）；注册 `beforeunload` 保存当前模式。

**「狸猫换太子」自动聚焦**：若开启自动聚焦且 URL 不含 `?focus`，则 `chrome.tabs.create({url:'index.html?focus'})` 并 `window.close()` 原页，新页 `body.focus-transition` 过渡。

**时间刷新策略**：`setInterval(updateTime, 1000)` 而非 rAF——rAF 在标签页隐藏时暂停会导致时钟停走。

## 1.9 Service Worker 启动序列（background.js）

- `importScripts` 加载 `bg/` 5 个子模块（共享 SW 全局作用域）。
- `onInstalled`：创建右键菜单「剪藏到工作台」（contexts: selection）。
- `onStartup` + 启动时调用 `restorePomodoroState()` 恢复番茄钟。
- 注册 `chrome.alarms.create('task-due-check', {periodInMinutes: 15})`。
- `onMessage` 分发：POMODORO_START/PAUSE/RESUME/STOP/GET_STATE、OPEN_SIDE_PANEL、RESOLVE_FAVICON。
- `onConnect`：管理 `pomodoro` 命名长连接端口。
- `notifications.onClicked`：点击番茄钟/任务到期通知跳转回 index.html。

## 1.10 模式切换（daily ↔ workbench）

- `state.currentDevhomeMode`：`'daily'` | `'workbench'`。
- 进入工作台 `enterFocusMode()`：切 `body` 类、显示 `#devhomeStage`、顶部工具栏切换。
- 返回日常 `showDailyMode()` / `exitFocusMode()`。
- `beforeunload` 将非 daily 模式写入 `localStorage('_devhome_last_mode')`，reload 后恢复。

## 1.11 核心约定与反模式红线

- **禁止魔法值**：裸数字/字符串/状态码需提取为具名常量或 enum。
- **外部输入必校验**：消息体、DOM 取值、JSON 解析先 `zod.safeParse` 或类型守卫（本项目多数用防御性正则与类型检查）。
- **错误处理**：统一异常体系（`js/lib/errors.ts` 若存在），禁止裸 `throw "xxx"`。
- **日志**：统一日志入口 `ns.logger`，禁止 `console.*` 散落（注意：本项目大量模块实际仍用 `console.log`，属于待重构项，见第 13 章）。
- **禁止浏览器原生弹窗**：用 `ns.showConfirm` / `ns.showToast` / `ns.showPrompt` 替代。
- **交互日志**：交互事件需输出 `[交互]/[面板]/[编辑]/[警告]/[错误]` 前缀日志。
