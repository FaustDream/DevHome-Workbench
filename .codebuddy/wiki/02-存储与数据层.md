# 02 存储与数据层

> 本项目的存储是**三层架构**：`localStorage`（同步、快）+ `chrome.storage.local`（异步、可靠、多上下文共享）+ 文件系统（备份/恢复）。所有业务模块经 `dataService` / `storageV2` 读写，隔离底层实现。

## 2.1 存储分层全景

```
┌────────────────────────────────────────────────────────────┐
│  文件系统 (File System Access API)                          │
│  devhome-config.json —— 配置/数据完整备份（fileConfig）       │
├────────────────────────────────────────────────────────────┤
│  chrome.storage.local（异步，SW 与页面共享）                 │
│  v2/ 前缀键：config notes captures tasks notebooks          │
│              pomodoro_sessions behavior encouragement_pool  │
│              pomodoro_state pages pageNames taskNotifySettings│
├────────────────────────────────────────────────────────────┤
│  localStorage（同步，页面内快速访问 + 缓存）                  │
│  tabpage_* 前缀（旧磁贴体系）  devhome_* 前缀（工作台旧数据） │
│  devhome_v2_cache_*（v2 缓存）  devhome_v2_meta_*（元数据）  │
│  其他：countdowns wallpaperImage wallpaperSettings           │
│        tabpage_weather_cache daily_greeting_card_quote 等    │
├────────────────────────────────────────────────────────────┤
│  IndexedDB（favicon 数据库，openFaviconDB）                  │
└────────────────────────────────────────────────────────────┘
```

## 2.2 `js/storage.js` — localStorage 抽象层

**挂载点**：`ns.storage`、`ns.devhomeStorage`、`ns.backupPagesSnapshot`

**职责**：封装 localStorage 读写，自动加前缀，并在写入时触发文件配置脏标记。

| API | 签名 | 说明 |
|-----|------|------|
| `ns.storage.get` | `(key, fallback)` | 读 `tabpage_<key>`，JSON.parse，失败返回 fallback |
| `ns.storage.set` | `(key, value)` | 写 `tabpage_<key>`，成功后 `fileConfig.markDirty()` |
| `ns.storage.clear` | `(key)` | 删 `tabpage_<key>` |
| `ns.devhomeStorage.get/set` | 同上 | 前缀为 `devhome_`，用于工作台旧配置 |
| `ns.backupPagesSnapshot` | `(reason, pagesData, pageNames)` | 磁贴数据变更前自动备份，最多 3 份（`tabpage_page_backups`） |

**关键存储键**（`tabpage_` 前缀）：

| 键 | 类型 | 用途 |
|----|------|------|
| `pages` | Array | 磁贴分页数据（每页含 tiles 数组） |
| `page_names` | Array | 分类名列表 |
| `pages_backups` | Array | 页面快照备份（≤3 份） |
| `search_history` | Array | 搜索历史（≤20 条） |
| `shortcut_size` / `shortcut_columns` | String | 快捷方式尺寸/列数 |
| `auto_focus` | Boolean | 自动聚焦开关 |
| `category_memory` | Boolean | 分类记忆开关 |
| `last_page` | Number | 分类记忆恢复的页码 |
| `cat_row` | Boolean | 分类按钮行开关 |
| `page_transition` | Boolean | 页面切换动画 |
| `engine` | String | 当前搜索引擎 |
| `tabpage_view_scale` | String | 视图缩放比例（Ctrl+/Ctrl-） |
| `linkNewTab_tiles` / `linkNewTab_search` | String('true'/'false') | 磁贴/搜索结果新标签打开 |
| `config_nickname` | String | 昵称 |
| `tabpage_layout_config` | JSON | F5 布局配置 |

## 2.3 `js/storageV2.js` — chrome.storage.local 抽象层

**挂载点**：`ns.storageV2`

**职责**：带 `v2/` 前缀的异步读写；localStorage 缓存加速；乐观锁并发控制；旧数据迁移；外部变更监听；配额监控。

### 2.3.1 KEYS 常量

```js
ns.storageV2.KEYS = {
    CONFIG: 'config',                 // v2/config
    NOTES: 'notes',                   // v2/notes
    CAPTURES: 'captures',             // v2/captures
    TASKS: 'tasks',                   // v2/tasks
    NOTEBOOKS: 'notebooks',           // v2/notebooks
    POMODORO_SESSIONS: 'pomodoro_sessions', // v2/pomodoro_sessions
    BEHAVIOR: 'behavior',             // v2/behavior
    ENCOURAGEMENT_POOL: 'encouragement_pool' // v2/encouragement_pool
};
```

另有非 KEYS 常量键：`v2/pomodoro_state`（番茄钟状态）、`v2/taskNotifySettings`（任务通知设置）、`v2/pages`、`v2/pageNames`。

### 2.3.2 核心 API

| API | 签名 | 说明 |
|-----|------|------|
| `get` | `(key, fallback)` → Promise | 读 `v2/<key>`；不可用时降级读 localStorage 缓存；读到后写缓存 |
| `set` | `(key, value)` → Promise | 乐观锁写 + 写缓存 + 标记文件脏 |
| `remove` | `(key)` → Promise | 删 `v2/<key>` + 清缓存 |
| `getAll` | `()` → Promise | 批量读取 8 个已知键（优化：传 key 数组而非 get(null)） |
| `migrateFromLegacy` | `()` → Promise | 从 `devhome_workbench` 迁移任务数据到 `v2/tasks`（幂等） |
| `isAvailable` / `isCacheExpired` / `getCacheRemainingTTL` | — | 可用性/缓存状态 |
| `getQuotaInfo` / `checkQuota` | — | 配额监控（90% 告警，30s 节流） |

### 2.3.3 乐观锁算法（关键算法）

`set()` 采用「读取-比较-写入」三步重试（最多 `MAX_RETRY=3`）：

1. 读 `v2/<key>` 当前值，取 `_version`（无则 0）。
2. 构造新值：**对象**类型 → 浅拷贝后附加 `_version: newVersion`；**数组/基本类型** → 包装为 `{data: value, _version: newVersion}`。
3. 写入 `chrome.storage.local`。
4. 写后立即读回，校验 `_version === newVersion`；不匹配（被其他标签页覆盖）则重试。
5. 重试 3 次失败：`logger.error` + `showToast('数据保存失败，请刷新页面后重试', 'error')`。

**解包规则 `unwrapValue`**：`{data, _version}` 两字段对象 → 返回 `data`；其余原样返回。

### 2.3.4 localStorage 缓存

- 缓存键：`devhome_v2_cache_<key>`，结构 `{value, _cacheTime}`。
- TTL：24h（`CACHE_TTL_MS`）；过期日志提示但不清除。
- 外部变更监听：`chrome.storage.onChanged` 中，凡 `v2/` 前缀变化 → 同步更新/删除缓存，保证 SW 写入后页面端缓存一致。

### 2.3.5 数据迁移（migrateFromLegacy）

- 幂等：`v2/tasks` 已存在 → `already_migrated` 跳过。
- 源：`devhome_workbench.quadrants[q].tasks`（q=q1~q4）。
- 目标：`v2/tasks` 扁平数组，每任务带 `quadrant` 字段，补齐 `id/title/description/status/noteId/pomodoroCount/createdAt/completedAt/cancelledAt`。

### 2.3.6 文件同步映射

`set()` 末尾按 key 映射 category 触发 `fileConfig.markDirty(category)`：

```
notes→'notes'  captures→'captures'  tasks→'tasks'  notebooks→'notebooks'
pomodoro_sessions→'pomodoro'  behavior→'behavior'  config→'config'
```

## 2.4 `js/dataService.js` — 统一数据服务门面

**挂载点**：`ns.dataService`

**职责**：统一封装三层存储，提供业务级语义 API。读优先 localStorage 缓存，写同时写 localStorage + chrome.storage；chrome.storage 不可用时降级 localStorage。

### 2.4.1 API 清单

| 分类 | API | 底层 |
|------|-----|------|
| 磁贴 | `getPages` / `savePages` / `getPageNames` / `savePageNames` | chrome.storage `v2/pages`、`v2/pageNames` + `tabpage_pages` |
| 笔记 | `getNotes` / `saveNote` / `deleteNote` | storageV2.KEYS.NOTES |
| 捕获 | `getCaptures` / `saveCapture`（≤200 条）/ `deleteCapture` | storageV2.KEYS.CAPTURES |
| 任务 | `getTasks` / `saveTask` / `deleteTask` | storageV2.KEYS.TASKS |
| 笔记本 | `getNotebooks` / `saveNotebooks` | storageV2.KEYS.NOTEBOOKS |
| 配置 | `getConfig` / `saveConfig` | storageV2.KEYS.CONFIG |
| 通用设置 | `getSetting` / `setSetting` | `tabpage_*` |
| 工作台设置 | `getDevhomeSetting` / `setDevhomeSetting` | `devhome_*` |
| 快照 | `exportAll`（v3.0 全量）/ `importAll` | 汇聚全部数据 |
| 工具 | `isChromeStorageAvailable` | — |

### 2.4.2 缓存设计（dataService 内部）

- 键 `tabpage_*`，缓存结构 `{_v: value, _ts: Date.now()}`，TTL 24h。
- `cacheGet` 过期则返回 fallback；`cacheSet` 写带时间戳。

## 2.5 `js/fileConfig.js` — 文件系统配置同步

**挂载点**：`ns.fileConfig`

**职责**：通过 File System Access API 将配置/数据同步到本地 `devhome-config.json`，实现备份与跨浏览器迁移。依赖浏览器对该 API 的支持（`isSupported()`），不支持时优雅降级。

### 2.5.1 核心 API

| API | 说明 |
|-----|------|
| `init()` → Promise<{ready, dirName}> | 恢复已授权目录句柄，读取配置文件 |
| `pickDir()` → Promise<boolean> | 弹出目录选择器，建立目录句柄并持久化授权 |
| `markDirty(category?)` | 标记数据脏，触发防抖（storage 写入 3s / storageV2 写入 1s）写盘 |
| `syncToFile()` → Promise | 立即将全部数据写入 `devhome-config.json` |
| `_tryRecoverRead` / `_tryRecoverWrite` | 尝试恢复已授权的读/写权限（权限过期后 re-request） |
| `updateBadge(text, color)` | 设置 action badge 指示同步状态 |
| `hideWarningBar()` | 隐藏同步警告条 |
| `isSupported()` | 浏览器能力检测 |

### 2.5.2 数据流向

```
页面任意 storage.set / storageV2.set
        │ markDirty(category)
        ▼
   防抖定时器（3s / 1s）
        ▼
   syncToFile()：读取全部数据 → 序列化 → 写 devhome-config.json
```

### 2.5.3 权限恢复流程（配置目录选择按钮点击）

1. `_tryRecoverRead()` → 成功则 `hideWarningBar` + `updateBadge` + `syncToFile` + `_reloadAfterConfig`。
2. 否则 `_tryRecoverWrite()` → 同上。
3. 否则 `pickDir()` → 成功后 `state.configReady=true` + `_reloadAfterConfig` + `bindEvents()`。

## 2.6 IndexedDB — favicon 数据库

`openFaviconDB()`（定义于 favicon.js 或 dataService 层）：缓存站点真实 favicon 的 dataURL，避免每次重复请求 SW 解析。SW 解析结果经 `RESOLVE_FAVICON` 消息回传后写入。

## 2.7 数据模型汇总（v2 存储）

### 2.7.1 笔记（v2/notes）

```js

  id: 'note_<ts>_<rand>',      // 唯一 ID
  title: '无标题',

  wordCount: 0,                // 中文字符+英文单词数
  type: 'note' | 'idea' | ... | 'custom_<key>',
```

## 2.8 重构要点（存储层）

1. **三层存储职责有重叠**：`dataService` 与 `storageV2` 有重复封装，需明确单一权威入口。
2. **乐观锁是「弱」实现**：基于读-写-验证，非真正 CAS；多标签页高频写入仍有冲突窗口。
3. **魔法值**：`CACHE_TTL_MS=24h`、`MAX_RETRY=3`、配额阈值 0.9 等已提取为常量，但 `storage.js` 中仍有散落数字。
4. **缓存一致性**：`dataService` 的 `{_v,_ts}` 缓存与 `storageV2` 的 `{value,_cacheTime}` 缓存是两套体系，易混。
5. **fileConfig 权限恢复逻辑复杂**：`_tryRecoverRead/Write` + `pickDir` 三岔流程可抽为状态机。
