# 06 工作台系统

> 本章覆盖专注模式（workbench）下的核心业务：四象限任务、番茄钟、日历、行为仪表盘、工作台笔记，以及工作台模式编排入口。

## 6.1 `js/workbench.js` — 工作台编排入口

**挂载点**：`ns.workbench`（或直接 ns 级方法）

**职责**：工作台模式的进入/退出、顶部工具栏、悬浮侧边栏、模式切换逻辑。业务已拆分到 `workbench_private/` 子模块。

### 6.1.1 工作台模式相关 API

| API | 说明 |
|-----|------|
| `ns.enterFocusMode()` | 进入工作台（专注）模式 |
| `ns.exitFocusMode()` / `ns.showDailyMode()` | 返回日常模式 |
| `ns.toggleFocusMode()` | 切换（快捷键触发） |
| `ns.isFocusModeShortcut(e)` | 判断是否命中专注快捷键（`focusShortcut` 配置） |
| `ns.toggleQuadrantSidebar()` | 折叠/展开四象限侧栏 |
| `ns.toggleQuadrantFilter()` | 活跃/全部任务过滤切换 |

### 6.1.2 专注模式快捷键

- 默认：`Ctrl+K`（`state._focusShortcut = {ctrl:true, shift:false, alt:false, key:'k'}`），可在设置中录制。
- 录制逻辑在 `settings-events.js` 的 `_bindShortcutRecorder`。

### 6.1.3 模式切换数据流

```
toggleFocusMode()
  → 设置 state.currentDevhomeMode
  → body class 切换（focus-transition / workbench-active）
  → 显示/隐藏 #devhomeStage
  → 顶部工具栏按钮切换（devhomeSettingsBtn、devhomeBackHome）
  → beforeunload 保存 _devhome_last_mode
```

## 6.2 `js/workbench_private/_quadrant-tasks.js` — 四象限任务

**挂载点**：`ns.*`

**职责**：四象限任务 CRUD、过滤、渲染、时间设置、截止提醒联动、状态规范化。

### 6.2.1 数据结构

`state.workbench.quadrants[q] = { title, tasks: [...] }`，`q ∈ q1~q4`。

任务：

```js
{
  id: 'task_<ts>_<rand>',
  title, description,
  status: 'active'|'completed'|'cancelled',
  noteIds: [],            // 关联笔记
  pomodoroCount: 0,
  dueDate: ISO|null,      // 到期通知
  plannedAt: <ts>|null,   // 计划时间
  createdAt, completedAt, cancelledAt
}
```

### 6.2.2 状态规范化 `normalizeTask`（关键算法）

- `status` 缺失 → 由 `completed` 推导（`completed ? 'completed' : 'active'`）。
- 补 `createdAt`。
- `plannedAt` 缺失且有 `deadline` → 迁移。
- `dueDate` 缺失且有 `plannedAt` → 由 `new Date(plannedAt).toISOString()` 生成。
- 删除旧字段 `completed`、`deadline`。
- `noteIds` 去重。

### 6.2.3 双存储同步（关键数据流）

`saveWorkbenchState(nextState)`：

1. `state.workbench = merge(getWorkbenchState(), nextState)`。
2. 写 `devhome_workbench`（localStorage 旧格式）。
3. **同时**扁平化四象限任务 → `v2/tasks`（storageV2），供 SW 任务到期通知使用。

`getWorkbenchState()`：读 `devhome_workbench`，与 `defaultWorkbenchState` 合并，四象限任务经 `normalizeTask` 规范化。

### 6.2.4 API 清单

| API | 说明 |
|-----|------|
| `ns.forEachQuadrant(fn)` | 遍历 q1~q4 |
| `ns.getQuadrantTasks(q)` | 取象限任务 |
| `ns.getOtherQuadrants(exclude)` | 排除指定象限 |
| `ns.getWorkbenchState()` / `ns.saveWorkbenchState(next)` | 读写工作台状态 |
| `ns.renderQuadrantBoard()` | 渲染四象限看板 |
| `ns.addTask(q, title, opts)` | 新增任务 |
| `ns.toggleTaskStatus(id)` | 切换完成/未完成 |
| `ns.updateTask(id, updates)` | 更新任务 |
| `ns.deleteTask(id)` | 删除任务 |
| `ns.convertNoteToTask(noteId, quadrant, plannedAt)` | 笔记转任务 |
| `ns.clearCompletedTasks()` | 清空已完成 |
| `ns.formatTaskTime(ts)` | 时间格式化（今天 HH:mm / 昨天 / 周几 / M/D） |

### 6.2.5 任务时间显示算法 `formatTaskTime`

```
today=今天 0 点；diffDays = (today - taskDay)/86400000
diffDays==0 → 'HH:mm'
diffDays==1 → '昨天 HH:mm'
diffDays<7  → '周X HH:mm'
否则        → 'M/D HH:mm'
```

### 6.2.6 过滤 `getVisibleTasks`

`_quadrantFilter`：'active'（默认，含 status 缺失/undefined）| 'all'。

### 6.2.7 笔记转任务流程

1. 笔记编辑器「转任务」按钮 `#wbNoteToTaskBtn` → 象限选择器 `#wbQuadrantPicker`。
2. 选象限 → 时间选择器 `#wbTaskTimePicker`（日期+时间，可跳过）。
3. 确认/跳过 → `convertNoteToTask(noteId, quadrant, plannedAt|null)` → toast「已转至 XX象限」。
4. 转换后笔记加 `noteIds` 关联，或直接创建任务并从笔记清空？

> 细节：转换在任务上记录 `noteIds`，并更新四象限看板渲染。

## 6.3 `js/workbench_private/_pomodoro.js` — 工作台番茄钟 UI

**挂载点**：`ns.*`

**职责**：番茄钟的页面端 UI 与控制逻辑（顶部常驻条 + 悬浮面板 + 旧版按钮兼容），与 SW 番茄钟核心（bg/_pomodoro-core.js）通过消息通信。

### 6.3.1 页面端 API

| API | 说明 |
|-----|------|
| `ns.startPomodoro(params)` | 开始（发 POMODORO_START 给 SW） |
| `ns.pausePomodoro()` | 暂停（POMODORO_PAUSE） |
| `ns.resumePomodoro()` | 恢复（POMODORO_RESUME） |
| `ns.resetPomodoro()` / `ns.stopPomodoro()` | 停止（POMODORO_STOP） |
| `ns.setPomodoroDuration(min)` | 设专注时长 |
| `ns.setPomodoroRestDuration(min)` | 设休息时长 |
| `ns.togglePomodoroMode(mode)` | 切换模式（default/focus） |
| `ns.setPomodoroMode(mode)` | 设模式 |
| `ns.togglePomodoroAutoCycle()` | 自动循环开关 |
| `ns.getPomodoroState()` | 拉取状态（POMODORO_GET_STATE） |

### 6.3.2 长连接与广播

- 页面建立 `chrome.runtime.connect({name:'pomodoro'})` 长连接。
- SW 每秒 `broadcastPomodoroState()` 向端口发 `{type:'POMODORO_STATE', data}`。
- 页面监听 `POMODORO_STATE` 更新顶部条/面板显示。
- 无端口时 SW 降级 `chrome.runtime.sendMessage` 单播。

### 6.3.3 UI 结构

- **顶部常驻条**：`#wbPomodoroTop`（`pomodoro-active` 类）、`#wbPomodoroTopStart`（开始/暂停）。
- **悬浮面板**：`#wbFloatingPomodoro`（`#wbFloatingPomodoroBtn` 触发）、`#wbFloatingPomodoroClose`。
- **旧版按钮兼容**：`wbPomodoroStart/Pause/Reset`、`.wb-pomodoro-preset[data-duration]`、`wbPomodoroCustom`、`wbPomodoroModeDefault/Focus`、`.wb-pomodoro-rest-btn[data-rest]`、`.wb-pomodoro-quick-btn[data-duration]`、`wbPomodoroRestInput`、`wbPomodoroAutoCycleBtn`。
- 悬浮面板互斥：打开一个关闭其他（`_toggleFloatingPanel`）。

### 6.3.4 与 SW 的状态机关系

```
页面 startPomodoro() ──POMODORO_START──▶ SW startPomodoro(params)
SW 每秒广播 POMODORO_STATE ◀── 长连接 ── 页面渲染
页面 pause/resume/stop ──消息──▶ SW 对应函数
SW 阶段结束（alarm）→ pomodoroPhaseEnd() → 通知 + 广播 → 页面自动更新
```

## 6.5 `js/workbench_private/_dashboard.js` — 行为仪表盘 + AI 面板

**挂载点**：`ns.renderBehaviorDashboard`、`ns.generateAI`、`ns.getModuleById`、`ns.getProviderById`、`ns.createOpenAIProvider`

**职责**：行为数据看板（连续打卡/番茄数/专注分钟/笔记数）、AI 调用引擎、供应商管理。

### 6.5.1 行为仪表盘

`renderBehaviorDashboard()`：

1. 读 `v2/behavior` 与 `v2/pomodoro_sessions`。
2. 统计：今日完成番茄数、总专注分钟（今日 sessions 的 duration 求和）。
3. **连续打卡逻辑**：今日无 `streakDay` → `streakDays+1`，写 `dailyStats[todayStr].streakDay=true`，持久化。
4. 组装 `window.__dashboardData = {streak, totalCompleted, totalPomodoros, totalFocusMinutes, totalNotes, dailyStats}`。
5. React 渲染：`ReactDOM.createRoot(#reactDashboardRoot)` 首次创建，后续 `window.__refreshDashboard()` 刷新；React 未加载则降级更新原生 DOM（`wbMeStreakNum`）。

### 6.5.2 AI 调用引擎 `generateAI(moduleId, userInput?)`

```
1. getModuleById(moduleId) 查模块定义
2. 读 v2/config.aiApi（activeProvider + providers 配置）
3. getProviderById(providerId) 查供应商元数据（含 API 适配器）
   未找到 → createOpenAIProvider(providerId, config) 用通用 OpenAI 兼容适配器
4. 合并配置：apiKey = providers[pid].apiKey || provider.apiKey
               endpoint / model 同理
5. 无 apiKey → toast「请先在下方配置 API Key」
6. 调用供应商请求（含流式/非流式），渲染 Markdown 回复
```

### 6.5.3 连续打卡算法（注意点）

- 每日首次渲染时若当日无 streakDay 记录即 +1；**重启浏览器可能重复 +1**（因为同日刷新页面会重新 renderBehaviorDashboard，但 dailyStats[todayStr] 已写入避免重复）。存在跨日边界与「当天已打卡但数据未写入」的竞态窗口。

## 6.8 重构要点（工作台系统）

1. **双存储双写**：任务同时写 `devhome_workbench` 与 `v2/tasks`，易产生不一致，需收敛为单一权威（建议 v2 为准，旧格式只读迁移）。
2. **连续打卡有重复计数风险**：需加「当日已记录」标志位与幂等保护。
3. **番茄钟 UI 有 v6 悬浮 + 旧版按钮并存**：旧版按钮是兼容包袱，可评估移除。
4. **四象限 `QUADRANTS` 数组在多个文件重复定义**（quadrant-tasks / export / storageV2 迁移），应集中常量。
5. **`convertNoteToTask` 与笔记模块耦合深**：需明确任务-笔记关联的语义（noteIds 双向往返）。
